# 大秘境机制与团队应对：实际日志可行性调查

调查日期：2026-10-18。

## 结论与验证范围

**可以从真实日志还原“哪个怪物的哪次技能造成全队伤害，以及治疗、坦克和输出如何应对”。** 本次已取得逐次命中、逐人增益、治疗/吸收事件与血量采样证据，不只是根据时间线推测。

样本来自项目已有报告 `XGdhCgWHtPpa9w6J`：第 2 场毒牙祭坛 +22、第 5 场密谋小径 +23。没有验证其排行榜位置，也没有把它们当作最优打法。第 2 场含实际死亡，因此也能验证产品如何识别失败的处理。

## 案例一：同一机制的三轮不同应对

密谋小径第 5 场，亵渎傀儡连续三轮“亵渎猛击”，分别在 **26:20.302、26:50.639、27:20.964** 完成施法。

每轮均在约 **0、4、8 秒** 出现三次命中，每次命中五名玩家，即每轮 15 条伤害事件。同一轮必须进一步分成三跳分析，不能用一个“本轮有开减伤”的标签代替。

| 轮次 | 治疗的实际动作及效果 | 其他成员的实际覆盖 |
|---|---|---|
| 第一轮 | +3.689 秒施放风暴涌流图腾，同时开始出现图腾治疗事件 | 猎人的优胜劣汰覆盖前两跳，第三跳不再存在；骑士第一跳没有圣佑术，第二、三跳有；治疗的星界转移覆盖第二、三跳 |
| 第二轮 | -4.804 秒使用盘魂者仪式容器；盘魂壁障的吸收事件直接注明伤害来自亵渎猛击，合计吸收 1,397,225 | 骑士前两跳有圣盾术且记录伤害为 0，第三跳已无圣盾术；猎人第二、三跳收到骑士的牺牲祝福 |
| 第三轮 | -0.703 秒施放灵魂链接图腾，-0.682 至 +5.334 秒有实际血量均衡事件；+8.046 秒施放风暴涌流图腾并开始记录治疗 | 战士前两跳有法术反射相关增益，第三跳不再存在；猎人第三跳有灵龟守护且记录伤害为 0 |

以上均为观察事实。“法术反射相关增益存在”不等于已证明整个机制被反射，也不代表可以把全部减伤量归因给一个技能。两种法术反射增益 ID（23920、385391）不应在产品里算成两次施法。

**直接吸收证据示例：**

```json
{
  "timestamp": 4415383,
  "type": "absorbed",
  "sourceID": 78,
  "targetID": 1,
  "ability": {"guid": 1307578, "name": "盘魂壁障"},
  "attackerID": 129,
  "extraAbility": {"guid": 1294827, "name": "亵渎猛击"},
  "amount": 339749
}
```

该事件同时给出了治疗者、承受者、护盾、攻击者、伤害技能和吸收量。第二轮共 5 条这样的相关吸收事件：四人在第一跳吸收，骑士在第三跳吸收。它不需要通过“附近开过饰品”来猜测关联。

## 案例二：区分高压来源、覆盖时段与失败结果

毒牙祭坛第 2 场的同一波里，“剧毒涌动”在 **20:43.733、21:10.398、23:32.455** 完成施法并开始伤害。

- 前两次来自同一个怪物个体：`sourceID=46, sourceInstance=2`。
- 第三次来自同类型的另一个个体：`sourceID=46, sourceInstance=4`。产品应显示为本波第 3 次该机制，同时保留个体身份，不能写成“同一只怪的第 3 次”。

| 次数 | 伤害记录 | 队伍应对与结果 |
|---|---|---|
| 第一次 | 持续约 9 秒，49 条玩家伤害事件；该技能占同一伤害窗口五人记录承伤的 50.87% | 坦克 +3.614 秒施放反魔法护罩。猎人 +8.031 秒死亡，治疗 +8.222 秒才施放灵魂链接图腾。不能把链接标成“提前覆盖整次 AOE”或成功保住猎人 |
| 第二次 | 持续约 7 秒，40 条玩家伤害事件；承伤占比 81.28% | 首跳时全队有集结呐喊；猎人收到骑士的牺牲祝福；治疗有星界转移；骑士有圣盾术。后者约 +0.468 秒消失，不能标为覆盖全部跳数。治疗 +0.001 秒施放风暴涌流图腾，记录到对应治疗 |
| 第三次 | 持续约 9 秒，50 条玩家伤害事件；承伤占比 58.95% | 首跳时战士有剑在人在/法术反射，猎人有优胜劣汰；骑士 +0.043 秒施放圣佑术，治疗 +0.465 秒施放星界转移，因此二者均未覆盖首跳。治疗 +1.423 秒使用盘魂者仪式容器，后续有明确吸收该机制伤害的盘魂壁障事件 |

承伤占比按该技能首跳至末跳窗口的玩家伤害事件 `amount` 求和计算；不包含吸收和死亡溢出。不是整波占比，也不是“治疗压力”的唯一指标。第二次的跳数较少，不能用三次累计伤害差异直接计算某个减伤技能的收益。

另取三个短战斗回放片段，分别包含 5,732、4,096、7,290 条各类事件。回放中的 139 条剧毒涌动伤害，与独立伤害事件接口按时间、来源个体、目标、技能、伤害及吸收字段逐条吻合。回放也包含五人血量采样和死亡、战复事件，足以进一步展示伤害前后血量变化；没有把离散采样假装成连续精确血线。

## 实现依据与当前缺口

本次沿用项目现有 WCL 会话，只进行了读取。伤害、治疗事件端点的参数结构通过 WCL 当前报告页面加载的官方 JavaScript 确认。按 `nextPageTimestamp` 翻页；治疗结果包含图腾等宠物来源，需要根据 `friendlyPets.petOwner` 归属到治疗者。

现有代码已经有波次、玩家施法和部分增益区间，但正式实现需要补齐：

1. **原始事件层。** 当前大秘境返回的每波承伤/治疗汇总不足以支持逐跳关联。应读取并缓存需要的伤害、治疗、吸收事件；血量可按需读取短回放片段。回放较大，本次 16 秒片段约 2.2–4.1 MB，不适合一开始总是加载整场完整事件。
2. **机制映射。** 施法、伤害、减益、周期伤害可能使用不同 ID。本次只手工验证了上述映射。名称和时间接近只能作为候选，正式支持应按副本/版本维护并验证规则。
3. **读条完成记录。** 当前 `event_list()` 对图表的事件对只返回第一项。本次敌方图表的第一项经常是 `begincast`，第二项才是 `cast`；调查脚本读取了两项并分别处理，避免把读条开始当命中时刻，或遗漏施法完成。
4. **按命中判断覆盖。** 伤害事件的 `buffs` 可提供目标在该次命中时的增益快照；增益事件用于追溯施放者和持续时间。首跳、后续跳、伤害后治疗必须分开标记。区域技能、敌方减益类减伤、装备和天赋效果不能只靠现有 `defensive` 列表。
5. **正确分类效果。** 团队治疗、个人减伤、外部减伤、提高生命上限、吸收、血量均衡、免疫应分开。灵魂链接的血量均衡日志同时有 `heal` 和 `damage`，不能把所有记录都简单相加当成治疗量。
6. **稳健识别全队机制。** 本次亵渎猛击的部分事件 `isAoE=false`，但实际同一轮三跳均命中五人。不能只用该布尔值筛选团队伤害。
7. **证据等级。** 明确区分直接归因的伤害/吸收、命中时的增益覆盖、附近发生的治疗，以及未经验证的战术意图。尚不能从单份日志推导唯一最优方案或精确反事实减伤收益。

## 复核产物

本次没有修改产品页面、服务端逻辑或技能分类。所有原始响应和临时调查脚本保存在 Git 忽略的 `cache/investigation/`；只有此调查说明作为文档新增。

- `cache/investigation/fetch_probe.py`：分页读取器，原始响应按请求单独缓存；不会自动打开人机验证窗口。
- `cache/investigation/analyze_pressure.py`：离线复核脚本，输出 `pressure_evidence.json`。
- `cache/investigation/pressure_evidence.json`：四个机制的逐次伤害、逐人减伤快照、相关施法/治疗事件和交叉校验结果。

运行已有本地证据的复核：

```sh
.venv/bin/python cache/investigation/analyze_pressure.py
```

结果：4 个机制、14 次完成施法、509 条玩家伤害事件全部关联；139 条伤害通过独立回放逐条复核；盘魂壁障直接吸收亵渎猛击的 5 条事件合计 1,397,225，断言通过。

**产品判断：可以先实现“指定机制 → 每次释放 → 每跳承伤与全队应对”的学习视图。已证明可以提供用户要求的核心信息；跨所有副本自动识别机制、评价打法优劣，是后续独立工作。**
